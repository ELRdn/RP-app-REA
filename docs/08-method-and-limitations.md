## 3. ツール

### 3.1 REA（Reverse Engineering Anything）

| ツール | 用途 | 結果 |
|---|---|---|
| `get_navigation_context` | セッション状態の確認 | 初期はターゲット未選択で `target_unavailable` |
| `analyze_javascript_application` | 本番JSの静的解析 | Zeta 109ファイル / SynClub 38ファイル / MiraiMind 22ファイル / CrushOn 106ファイル |
| `inspect_analysis_view` | サマリービュー | 統計・カバレッジ・制約 |
| `export_evidence_bundle` | 証拠の書き出し | 192MBのため**リポジトリには含めず**（サイズ超過） |

REAの分析は**入力ディレクトリのハッシュ**（Zeta `26bdb2d7…`）で固定され、同じ入力に対して再現可能です。セマンティック解析は結果バジェットの制約で部分的でしたが、**ファイル単位の静的ファクト（サイズ、ASTノード、findings、parse failure）**は保持されています。

### 3.2 ブラウザキャプチャ

- システムChrome（`C:\Program Files\Google\Chrome\Application\chrome.exe`）+ `playwright-core`
- viewport **390×844 / DPR2**、`isMobile: true`、`hasTouch: true`、`locale: ja-JP`、`timezoneId: Asia/Tokyo`
- UA：iPhone 17.5 Safari相当
- 待機：`domcontentloaded` + 3.5–7秒（SPAのハイドレーション待ち）
- オーバーレイ（アプリ誘導モーダル、広告）は**UI要素として別途キャプチャ**した上で閉じ、下の画面を撮影
- スクロールは**内部スクロールコンテナ**を特定して操作（`window.scrollTo` が効かないページがあるため）
- デスクトップは **1280×900 / 1440×900 / DPR1**

DNSが間欠的に失敗したため、ナビゲーションは最大5回リトライ。失敗した画面は再取得しています。

### 3.3 トークン抽出

- 本番CSSのユーティリティ定義（`.bg-primary-400{...#6728ff}` など）を正規表現で抽出
- 実画面の `getComputedStyle` で、表示中の要素の色・フォント・角丸・影を集計
- 両者を突き合わせ、**CSSに存在するが使われていない色**と**実際に使われている色**を分離
- コントラスト比はWCAG 2.xの相対輝度式で計算

### 3.4 ストア / ネットワーク

- iTunes Lookup API（`country=jp`）で最新バージョン、評価、スクリーンショット、説明文
- HTTPレスポンスヘッダ（Vercel/Nuxt/APISIX、HSTS、RateLimit、Cookie属性）
- `manifest.json`、`robots.txt`、`sitemap.xml`
- Playwrightの`request`イベントで、公開ページが実際に叩くXHR/fetchの**ホストとパス**を記録（本文は保存せず）

### 3.5 UX計測

「最初のAI応答」までの導線を、5製品で同一のハーネスにより計測しました。

- 入口URLから、最初のキャラクターカードをタップ
- 主CTA（`トークを始める` / `チャットを始める` / `進む` / `プレイする`）をタップ
- 中立のプロンプト `こんにちは。今日は何をしていますか？` を送信
- 最初のAI応答（またはゲート）までの**タップ数・画面遷移・時間**を記録
- タップ領域は `getBoundingClientRect` で44px未満をカウント
- 文字サイズは computed style で12px未満をカウント
- セマンティック要素は `a, button, [role=button], input, textarea, select` の可視要素
- LCP/CLSは `PerformanceObserver`、通信量は `performance.getEntriesByType('resource')` の `transferSize` 合計

**注意**：時間はシングルサンプルで、SPAの固定待機（3.5〜7.5秒）を含みます。絶対値ではなく、**タップ→次画面**と**送信→応答**の差分を比較してください。SynClubとCrushOnはゲスト送信不可、**オズチャットはログイン必須**のため、応答時間は存在しません。

### 3.6 オズチャットの認証境界

オズチャットは5製品で唯一、**アプリの全ルートがログイン必須**です。

- `/`、`/room`、`/app/*`、`/notifications` などは `302 → /auth/signin?redirect_to=...`
- 未認証で到達できるのは、ログイン、FAQ、規約、サポート、共有カード、一部イベント、エラー画面のみ
- 認証後のホーム／チャット／ストアは実キャプチャしていない
- 代わりに、App Storeの公式スクリーンショット8点と公開Wiki/マガジンでUIを補完
- 共有カードとハロウィンは画像をブラーし、ビキニイベントは収録しない

このため、オズチャットの「チャットまでのタップ数」「送信→応答」は**N/A**とし、マーケティング→ログインのハンドオフ（2.8〜3.0秒）、認証UI、共有カード、パフォーマンスを実測値として採用しています。

## 4. 証拠の階層

本レポートは、証拠の強さを3段階で区別します。

| 階層 | 意味 | 例 |
|---|---|---|
| **Observed（観測）** | 未認証の実画面・実レスポンスで確認 | ホームのカード寸法、ログインシート、QRゲート |
| **Derived（派生）** | 本番CSS/JS/DOMの静的事実から導出 | トークン値、コンポーネント名、ルート、未使用の決済UI |
| **Inferred（推測）** | 文脈・ストアコピー・設計意図からの推測 | サブスクの価格、ABテスト、WebSocketの用途 |

「未確認」は**Unknown**として残し、推測で埋めていません。特に、ログイン後にしか見えない画面（`/subscription`, `/chat`, `/agent/*`）は、CSS/バンドル内の**存在表明**にとどめています。

## 5. やっていないこと

- **認証回避**：ログイン、SMS、OAuthの突破はしていません
- **非公開APIの叩き込み**：公開ページが自発的に呼ぶエンドポイントの記録のみ
- **APK/IPAの取得・解析**：ストアからのバイナリ取得は行っていません。モバイルUIはストア素材と提供スクリーンショットのみ
- **負荷試験 / スクレイピング**：レート制限を尊重し、1ページあたり数回のアクセス
- **UGCの再配布**：本文は公開用に選定・モザイク。DOMはテキストを除いた構造アウトラインのみ
- **パフォーマンス計測**：LighthouseのPerformanceカテゴリは未実行（a11y/BP/SEOのみ）

## 6. 限界

### 6.1 動的UI / A/Bテスト

両社とも頻繁にUIを更新し、A/Bテストをしています。本レポートの画面は**2026-10-24〜25のスナップショット**です。同じURLでも、地域・端末・アカウント・キャンペーンで異なる画面が出る可能性があります。特に：

- ZetaのAIプロットアシスタントは、同じURLでも**ウィザードが出る場合と出ない場合**がありました（`z38` はウィザード、後日の再取得はモーダルのみ）
- Zetaのホーム/ランキングのカード内容は毎回ランダムに近い
- SynClubのキャラフィードは毎回内容が変わる

### 6.2 ゲートされた画面

以下は未ログインで到達できず、**UIの実物を確認していません**：

- Zeta：`/subscription`、`/settings`、`/plots/create` の完了画面、購入フロー
- SynClub：`/chat`、`/subscription`、`/agent/{id}`、`/payment-*`、`/voice/factory`、`/drama`
- MiraiMind：`#/create`、`#/settings`、VIP/サブスク、心の声・アーカイブ・ギフトの実機能
- CrushOn：`/ja/store`、`/ja/account`、送信、グループVIP、クリエイター収益、購入フロー

これらはCSS/バンドル内のクラス名・文字列から**存在と構成**を推定していますが、実際のレイアウト・文言・色は不明です。

### 6.3 モバイルアプリ

- Zeta：iOS実機8点（提供者）＋ストア10点。**全画面ではない**（オンボーディング、購入、通知、設定のサブ画面など）
- SynClub：ストア9点のみ。**実機キャプチャなし**。アプリのダークUI、音声通話、表情、背景切替はストア素材の再現イメージであり、実装の詳細は不明
- MiraiMind：Google Play素材5点＋Webアプリ。iOSはストアページが取得できず（`lookup` 0件）、**iOS実機は未取得**
- CrushOn：iOSアプリなし（Android `ai.crushon.app` のみ）。**アプリの実機キャプチャは未取得**。Webアプリのモバイル/デスクトップが主証拠

### 6.4 REAのセマンティック解析

- Zeta：109ファイル中、多くのチャンクで「セマンティックグラフが結果バジェットを超過。静的ファクトは保持」
- SynClub：38ファイル中、一部で同じ制約
- したがって、**呼び出し関係・データフローの完全なグラフ**は得られていません。本レポートの実装主張は、静的文字列とDOM属性に依存しています

### 6.5 コンテンツの代表性

- Zetaのプロット/チャットはUGCで、内容は日々変わります。特定のプロット（例：「お腹が壊れてる幼馴染」）の画面は、UI構造の例として選んだもので、人気や品質を代表するものではありません
- SynClubのフィードは成人向けの内容を含みます。公開用に選定・レダクトしていますが、元の分布はより多様です

### 6.6 法務・倫理

- スクリーンショットの権利は各社・各クリエイターに帰属します。本リポジトリは**分析・批評目的**の引用であり、再配布許諾ではありません
- 実機スクリーンショットは提供者の同意を得て収録しています
- 成人向けUGCは公開用に除外/モザイクしています
- 削除要請があれば該当画像を差し替えます

## 7. 再現手順（要約）

1. ChromeとNode.jsを用意
2. `playwright-core` をインストール
3. 390×844 / DPR2 / ja-JP のコンテキストで対象URLへ
4. アプリ誘導モーダルを閉じ、内部スクロールコンテナを操作しながらスクリーンショット
5. 本番CSSを取得し、`bg-*` / `text-*` / `font-size` / `border-radius` を抽出
6. バンドルを保存し、REA `analyze_javascript_application`（`detail: summary`）で統計を取得
7. `data/screens.json` にメタデータとSHA-256を記録

完全なスクリプトはリポジトリには含めていません（対象サイトへの負荷と再配布の観点）。必要なら、キャプチャ条件とセレクタをこのドキュメントから再構成できます。
